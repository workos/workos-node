# WorkOS Node SDK — Agent Context

Much of this repository is **auto-generated** by the oagen pipeline from the
WorkOS OpenAPI spec. Some older services are still hand-maintained.

## The generation pipeline

| Repo                                                              | Role                                                                                                                                       |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| [workos/openapi-spec](https://github.com/workos/openapi-spec)     | Source of truth for the API surface (the OpenAPI spec, exported by the WorkOS API) and the orchestration entrypoint for all SDK generation |
| [workos/oagen](https://github.com/workos/oagen)                   | The generator engine (spec → IR → code)                                                                                                    |
| [workos/oagen-emitters](https://github.com/workos/oagen-emitters) | The per-language emitters, including the Node emitter that produces this repo's code                                                       |

Regeneration runs from a checkout of `openapi-spec`, never from this repo:

```bash
npm run sdk:generate -- --lang node --output workos-node
```

## Generated vs. hand-maintained code

- Generated files begin with the header `// This file is auto-generated by oagen. Do not edit.` — treat them as build artifacts. `.oagen-manifest.json` lists them.
- Hand-maintained code is fenced with `@oagen-ignore-start` / `@oagen-ignore-end` markers, lives in files marked `@oagen-ignore-file`, or has no generated header. Only this code is editable in this repo.

Don't hand-edit a file that has the generated header — the next
`sdk:generate` run silently overwrites it. Instead, fix the emitter or the
spec upstream and regenerate.

## Spelling

Write American English in hand-maintained code, comments, docs and test names
(`behavior`, `canceled`, `honor`), per the
[WorkOS writing style guide](https://app.notion.com/p/workos/Writing-In-Our-Product-6975915fa9a74150916c669d562afe16#5d75728e33a040efa879e598340b8523).
Never respell a name or value that already ships: exported types, methods,
options, API fields and enum values, fixture payloads, generated files, and
third-party identifiers keep their spelling.
